# ⚠️  MAINTENANCE RULE — READ BEFORE EDITING
# Under RFC 9309 a crawler obeys ONLY the single most specific matching
# User-agent group and ignores "User-agent: *" entirely once a named group
# exists for it. That means EVERY named group below must repeat the full
# Disallow set — a named group inherits NOTHING.
#
# This is not theoretical: before 9 Aug 2026 the GPTBot / ClaudeBot /
# PerplexityBot / Google-Extended / anthropic-ai groups each contained only
# "Allow: /" with a comment claiming the write/admin blocks "above still
# apply". They did not. Those five agents had unrestricted access to
# /api/registry-purge, /api/backfill-genres and /api/enrich-entities —
# destructive endpoints reachable by an ordinary GET.
#
# When adding a new blocked endpoint: add it to EVERY group below, not just
# the first one. If you only edit one, you have reintroduced the same bug.
#
# Sitemap is a non-group directive (host-scoped, not group-scoped), so its
# position is functionally irrelevant — kept at the top for visibility.
#
# WHY THIS POINTS AT /api/sitemap?sec=index AND NOT /sitemap.xml:
# /api/sitemap?sec=index generates the sitemap index live with real
# per-section <lastmod> dates (see functions/api/sitemap.js — every date
# derives from the same data the child sitemaps emit per URL, never
# Date.now()). <lastmod> is Google's primary signal for which child sitemaps
# to re-fetch and how often, so on a continuously auto-committing registry it
# directly controls how fast new event pages get discovered. Pointing the
# directive straight at this URL needs no routing behaviour at all and cannot
# 404. Google accepts a sitemap at ANY URL; there is no requirement that it
# be named sitemap.xml or sit at the root.
#
# UPDATE (29 Aug 2026): /sitemap.xml itself now also serves this exact same
# dynamic content — functions/sitemap.xml.js was originally saved under the
# wrong filename (functions/sitemap-xml-function.js), which is why it 404'd
# on 9 Aug and was misdiagnosed then as "Pages Functions can't serve
# /sitemap.xml". It was renamed to the correct functions/sitemap.xml.js on
# 29 Aug and confirmed live serving 200 with accurate <lastmod> values — the
# static /sitemap.xml fallback file was removed at the same time, since the
# Function now covers that URL directly. This directive is left pointing at
# /api/sitemap?sec=index rather than switched to /sitemap.xml because it
# already works and is already submitted in GSC (see note below) — not
# because /sitemap.xml doesn't work. Either URL is correct today.
#
# "Allow: /api/sitemap" appears in every group below, so this is fetchable.
# ALSO SUBMIT THIS EXACT URL IN GSC > SITEMAPS — changing the directive here
# does not update what GSC is already tracking.

Sitemap: https://ticketscout.co.uk/api/sitemap?sec=index
